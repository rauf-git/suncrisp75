# Fix: keep-alive returns 404 "Requested function was not found"

## What the response tells us

The `/api/keep-alive` Vercel route is working — it reached Supabase and got a reply. The 404 comes from Supabase itself: the `keep-alive` Edge Function does not exist on the target project (`wpxhailrakxuswzleobh`).

The function source exists in this repo at `supabase/functions/keep-alive/index.ts` and is configured in `supabase/config.toml` with `verify_jwt = false`, but `config.toml` still carries `project_id = "oxoaoyvvgddqksvdmrkd"` (the original Lovable-managed backend). Edge functions were only ever deployed to that old project — none of the three functions (`keep-alive`, `send-contact-email`, `send-inquiry-email`) have been deployed to the client's new Supabase project.

## Fix

### 1. Deploy the three edge functions to the client's Supabase project

The client (or you, with their CLI access) runs from the repo root:

```
supabase login
supabase link --project-ref wpxhailrakxuswzleobh
supabase functions deploy keep-alive --no-verify-jwt
supabase functions deploy send-contact-email --no-verify-jwt
supabase functions deploy send-inquiry-email --no-verify-jwt
```

This is a CLI action on the client's account — it cannot be done from inside Lovable, since Lovable is still connected to the old backend.

### 2. Set the function secrets on the new project

`send-contact-email` and `send-inquiry-email` need `RESEND_API_KEY` on the new project. Set it in the client's Supabase dashboard under Edge Functions → Secrets, or:

```
supabase secrets set RESEND_API_KEY=<key>
```

`SUPABASE_URL`, `SUPABASE_ANON_KEY`, and `SUPABASE_SERVICE_ROLE_KEY` are injected automatically.

### 3. Re-test

Hit `https://<your-vercel-domain>/api/keep-alive` again. Expected: `{"ok":true,"status":200,...}`.

Also test the Supabase function directly:

```
curl -X POST https://wpxhailrakxuswzleobh.supabase.co/functions/v1/keep-alive \
  -H "apikey: <anon key>" -H "Authorization: Bearer <anon key>"
```

### 4. Verify the Vercel cron

- Vercel → project → Settings → Cron Jobs: confirm `/api/keep-alive` with schedule `0 0 */2 * *` is listed.
- After the next scheduled run, Vercel → Logs → filter for the cron invocation and confirm a 200.
- Cross-check in the client's Supabase dashboard → Edge Functions → `keep-alive` → Logs for a matching invocation.

## Note on `config.toml`

`supabase/config.toml` still points at the old project ref. It is auto-generated by Lovable and should be left alone while the project remains connected here; `supabase link` overrides it locally for the client's deploys. If the client wants the repo to be fully standalone, that file's `project_id` should be updated to `wpxhailrakxuswzleobh` after the project is disconnected from Lovable.
